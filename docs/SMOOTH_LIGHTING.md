# 平滑光照修正 v0.4.6（2026-11-02）

用户指出 v0.4.5 光影开启后像关闭平滑光照的 MC：树冠下、台阶与树干附近出现整格明暗变化。核对上一版实现可确认，每次命中只取一个体素的天空遮蔽/火光值，整个方块面保持同一亮度，没有角点光照或接触 AO。这是实现缺失，纹理分辨率和最近邻采样不需要改变。

## 调研与实现

用户提供的 [中文着色器百科](https://zh.minecraft.wiki/w/%E7%9D%80%E8%89%B2%E5%99%A8) 在本次工具抓取中不可用，没有将其内容当作已读依据。补充核对了两个直接来源：

- [Sodium SmoothLightPipeline 源码](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/model/light/smooth/SmoothLightPipeline.java)：邻域光照、面角亮度/AO 与插值分开处理。它是对原版的改进实现，不是原版源码。
- [0 FPS：体素环境遮蔽算法原文](https://0fps.net/2013/07/03/ambient-occlusion-for-minecraft-like-worlds/)：用两个侧邻居与一个对角邻居估计顶点遮蔽，说明角点光照与方块几何的关系。

没有引入这些项目的运行依赖或复制整套实现。本项目仍用 D3D11 Compute 逐像素命中体素，直接在命中面计算四角并插值，不需要先切换到三角网格。

1. 面外侧共享 3×3 采样模板，取得九个光照值和实心遮蔽标志。
2. 每个面角平均对应四份光照，结合两侧和对角的局部 AO；AO 最暗为 0.55，两个侧邻居均遮挡时采用最暗值。
3. 按命中点在面内的真实坐标对四角结果做双线性插值。相邻共面方块共享角点光照；法线继续保持立方体面方向，不把方块形状磨圆。
4. 再乘方向光、混合雾，最后应用原有燃烧/连通性/选区显示色。原纹理继续最近邻采样，叶片继续 alpha 裁切，UI 不变。

树叶和水不作为实心 AO 墙，防止把整块透明树冠涂成黑格。树叶仍参与天空光透过。采样遵守树冠隐藏、燃尽叶片/树干移除以及世界边界。天空与火光仍是有界代理，没有完整移植 MC 光照传播；本修正也没有新增真实投影阴影、SSAO 或水面反射。

原来的“光影 / Shader”开关现在启用这套平滑光照，不再增加一个重叠设置。GPU 关闭时行为不变。按用户要求将平滑光照与草甸草方块修正整理为 v0.4.6 同步；整体视觉继续由用户审查。

## 有效验证

`./build.ps1 -Verify`：**292 项原生检查通过**，日志 [smooth-lighting-checks.log](../artifacts/smooth-lighting-checks.log)。

新增实际 GPU 白色材质场景，将纹理变化从明暗测量中排除：同一地面方块靠近障碍的一侧产生至少八级单调渐变，限制内部单像素亮度突变；相邻共面边界连续，保持中性色与 alpha。原有开关精确恢复、燃尽、双图同步、CPU 回退等检查继续通过。

受控反例使用同一新测试程序，临时加载 Git HEAD 的旧着色器，并在 finally 中恢复当前文件：旧版本在“面内接触光渐变”断言处以 exit 1 失败，见 [反例日志](../artifacts/smooth-lighting-flat-control.log)。该预期失败单独保留，没有删断言或改阈值。

## 性能与截图

运行 `./forest-stress.ps1 -Benchmark -Shaders` 生成本次独立的 `smooth-lighting-*` 文件；之前 v0.4.5 的 `shader-*` 数据保留为历史记录。实际适配器 RTX 4060 Laptop GPU；ABBA 顺序、每组 16 帧预热和 48 帧采样，GPU 时间戳单独测量，方法沿用 [v0.4.5 记录](MC_SHADERS.md)。

| 场景 | 关闭 FPS | 开启 FPS | 关闭 GPU ms | 开启 GPU ms |
|---|---:|---:|---:|---:|
| 1280×860 工作台 | 70.96 | 70.79 | 0.21 | 0.96 |
| 同窗口火焰回放 | 71.29 | 68.33 | 0.33 | 0.47 |
| 2560×1380 工作台 | 71.30 | 72.16 | 0.70 | 2.27 |
| 同窗口火焰回放 | 71.30 | 52.03 | 0.75 | 3.81 |
| 1536 森林总览，大窗口 | 72.72 | 74.52 | 2.41 | 4.09 |
| 1536 森林局部，大窗口 | 74.05 | 69.71 | 1.74 | 8.45 |
| 1536 森林俯视，大窗口 | 73.85 | 73.94 | 0.40 | 4.52 |

表中 FPS 是两组均值，GPU 是两组 GPU 中位数均值。森林仍是 109,253 树模型的渲染诊断。当前直接在命中像素执行九份邻域光照采样，成本高于上一版的一份采样；未把角点光照预烘焙到区块缓存。12ms 帧间等待限制 FPS，开启 FPS 偶尔略高不能解释为算法加速。

大窗口火焰开启两组分别为 **33.91 / 70.15 FPS**，渲染中位数约 1.70/1.67ms，GPU 中位数约 2.49/5.14ms。保留这次明显的循环耗时波动，没有删除慢组或重测挑选较好结果。现有数据不足以区分调度、状态更新或运行时停顿的原因，因此不宣称火焰回放稳定 70FPS。后续若继续优化，需要分别记录完整帧周期、状态更新与等待时间。

原始数据：[CSV](../artifacts/smooth-lighting-benchmark.csv)、[运行日志](../artifacts/smooth-lighting-benchmark.log)。旧/新版实测分属不同运行，GPU 时钟波动明显，不能把历史中位数相减当作精确改进成本。
