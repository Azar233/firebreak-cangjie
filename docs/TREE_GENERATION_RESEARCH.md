# 树木生成调研（2026-11-02）

用户要求先不进入 P5，调研树木一致性、MC 原版生成和噪声的作用。本轮不修改生成器、传播模型或渲染实现。

## 当前项目的实际路径

工作台使用 `populateScene` 重建显示场景，清空 Scene 初始化样例后，仅在可燃林地中满足 `x%4==3 && z%4==3` 的位置调用 `Scene.tree`。因此当前是间距四格的固定栽植网格，不是 Scene.init 中那份早期 P0 坐标表，也没有使用 seed 或噪声选树位。

`Scene.tree` 在当地表面上放置四格高的同种原木，再在相对高度 2、3、4 放树叶：前两层半径 2，顶层半径 1，额外通过曼哈顿距离切去部分角落。所有实例都采用同一尺寸、材料和冠形。树冠遇越界、非林地/已处理列或已有方块时被截断，局部差异只是裁剪与遮挡。

数学模型读取 24×20 林地/处理掩码；画出的树是林地符号，不代表逐株树木或实测生物量。当前四格间距和冠宽接近，树冠也容易并成齐整的大块。

## 原版的生成思路

Java 版资料以 Fabric 文档所展示的原版 Feature/Placer 接口为依据，基岩版另参考 Microsoft 官方生成与 Tree Feature 文档。两版实现和字段不同，不把两套配置当成同一个格式；也不以示例参数声称精确复刻所有版本的原版橡树。

可以分成三层理解：生物群系选择植被组合；放置规则决定次数、候选位置、地表高度和条件；单树规则分别放置树干、树冠以及可选装饰。树不是必须载入的整株预制模型，而是由原木和树叶等方块程序化搭建。不同类型使用不同放置规则；同类树还可改变高度、冠形、枝条等参数。

Fabric 示例直接使用原版 `StraightTrunkPlacer`、`BlobFoliagePlacer` 和方块状态提供器；同时把特征定义与放置配置分开。Microsoft Tree Feature 列出可随机的树干高度、可生长/替换方块以及不同树干、冠层、根系等组件。这些资料支持“参数化规则＋受 seed 控制的随机变化”，不支持把所有树简化成一种噪声生成公式。

## 噪声与随机数

官方世界生成说明明确将地形和生物群系噪声与后续算法放置分开。噪声适合生成空间上连续的地形、区域和密度变化；伪随机数适合在给定候选位置抽取高度、半径、枝条方向等参数。常规单棵树的形状主要依靠树干/树冠规则，不是把 Perlin 或 Simplex 噪声直接变成一整棵树。

因此，当前重复感首先来自固定坐标网格和固定树形。加入噪声不是解决它们的必需条件。大范围森林疏密、成片树种或林窗才是后续可考虑噪声的地方，且不声称原版所有森林都使用同一种密度噪声。

## 适合本项目的建议（尚未实施）

1. 先增加几种有界树形：矮圆冠、高窄冠、偏冠/小分枝。同类树随机改变高度、冠宽、树叶角落和少量枝条，先复用已有橡木材料。
2. 打破四格等距感：在粗网格内做固定 seed 的位置扰动，检查林地、建筑、间距和场景高度。Poisson Disk 等最小间距采样也是可选方案，但不是在声称原版默认使用它。
3. 形状稳定之后再考虑桦树/云杉等材质和形态。当前燃尽逻辑按原木/树叶材料分类，增加新材料时需一并核对焦桩、叶片消失、火焰锚点与回放，不只加贴图。
4. 视觉随机与传播随机分开。使用稳定的视觉 seed、树根坐标和生成版本决定实例，不能每帧随机，也不应因为改变火势 seed 就重洗整片森林。
5. 基线与方案共用同一份基线树目录，只对处理区域过滤；不能删除一棵树后让顺序随机数错位，导致其它树也换形。否则对照画面会混入无关差异。
6. 当前场景高度只有 14 格，树形须有上界；暂不复刻巨型丛林树、完整生物群系或 MC 世界生成器。树形可以继续由仓颉生成现有体素数组，不必先更换渲染技术。

应优先改善显示层，同时保持林地、燃料、P3/P4 统计和预算结果一致。若未来想用噪声产生会阻断蔓延的真实林窗，必须把林窗同步落实到林地/燃料数据并单独定义模型变更，不能只在画面上删树却让用户误以为形成了隔离带。

后续验收重点：同 seed 重现、不同实例形状有差异、基线/方案实例一致、处理及回放稳定、无越界/穿建筑、燃料及统计不受纯视觉变化影响；性能须实测，不凭“原版算法”名称推断容量。整体自然感继续由用户审查。
