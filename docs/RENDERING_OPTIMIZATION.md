# 渲染优化 v0.4.2

保持仓颉业务与渲染代码、SDL 呈现，不启动 P5。本轮在 v0.4.1 的真实大森林基线上优化路线 A，没有引入外部引擎或 GPU shader。

## 实现

- 体素材质由 Int64 改为 UInt8，保留合法材质校验；1536²×14 原始存储从 252MiB 降到 31.5MiB。项目文件和仿真输入不变。
- 维护 8×8×8 占据计数，射线在空区块中跳至下一边界，区块内部逐体素遍历。插入、替换、移除、场地重建同步维护索引；只将完全没有基础体素的块视为空。燃尽仅减少几何，不会使跳空漏掉新几何。边角相交保留旧算法逐轴顺序。
- 每条射线的七组临时数组改为局部标量；纹理 alpha 测试、地面拾取与燃尽几何仍共享同一命中规则。
- RGBA32 批量写入遵守 Surface pitch、格式和行边界，一批只锁定/解锁一次，异常仍解锁，减少逐像素 FFI。
- 足够大的批次由四份 CPU 行任务计算到复用缓冲区，任务写不同行；所有任务完成后，主线程写入 Surface 和上传纹理。错误时也等待所有任务完成后才允许资源释放。小批次顺序处理，仍维持每轮最多 32 行、约 8ms 的补绘合同。
- 三维画布与整个场景包围盒的屏幕投影相交，交集之外直接写背景，不建立射线。射线法本来只计算视口内像素，不逐树提交视口外的整个世界。区块跳空负责沿可见射线减少空体素访问；没有声称这等同于 GPU 网格的视锥剔除。
- 大森林诊断默认使用正常近景尺度查看局部，F 回到局部，Home 总览。数据仍整体驻留内存；这是视图和计算裁剪，不是磁盘流式区块加载。Tab 保留正上方纹理图。

## 开源与原理参考

重新核对 [VoxelRT](https://github.com/dubiousconst282/VoxelRT) 的 PlainDDA / MultiDDA 两级格网对照，采用其分层跳空思想，算法以仓颉独立实现，没有移植 GPU shader 或将该项目加入依赖。直接像素访问遵循 [SDL_LockSurface 官方合同](https://wiki.libsdl.org/SDL3/SDL_LockSurface)。

[Sodium](https://github.com/CaffeineMC/sodium) 是可继续研究的 Minecraft 渲染器架构来源；当前仓库声明 Polyform Shield，不能笼统当作 MIT 代码复制。[此前调研](RENDERING_RESEARCH.md) 中 Voxy 同样只用于架构参考。原版/模组的 GPU 网格、材质批次、局部重建和 LOD 仍是未来另一条路线；本轮不将 Java 模组代码或其他语言框架嵌入应用。

## 正确性和实测边界

247 项原生检查通过。新增保留旧 DDA 作为验证参考，41,472 条射线覆盖密集/稀疏森林、多方向、alpha 树叶、燃尽阶段、隐藏树冠、俯视和地面拾取；另测区块边角的正反向相交、占据计数更新/清空、批量像素异常解锁。并行与串行逐像素一致，视口剔除与未剔除的射线颜色在完全可见、部分移出和全部移出时一致。默认局部相机不再将整个世界缩到窗口内。

基线为 v0.4.1 最终数据：[森林](../artifacts/forest-baseline.csv)、[真实工作台](../artifacts/forest-workbench-baseline.csv)。本轮最终数据：[森林](../artifacts/forest-benchmark.csv)、[真实工作台](../artifacts/forest-workbench.csv)。原有 CSV 列保留，局部视图额外记录平移指标，非局部案例平移列为 0（未测）。静止/旋转均预热 3 帧、采样 24 帧，保留每帧 12ms 等待、相同窗口/相机/密度/seed/原生分辨率/640px 预览策略。局部视图是新案例，不能拿局部和旧全景做加速比。单次渲染计时包括任务同步与像素拷贝，不把等待移出计时制造收益。

火焰回放用真实 24×20 工作台、传播概率 1、燃烧 3 步、预计算历史，每帧切换一次历史状态，调用正常显示状态更新、几何过滤和火焰精灵绘制。这比正常低频更新更频繁，但不是十万树同时燃烧的容量证明。本轮仍未扩展大森林的传播/规划模型，也没有大型火焰或烟雾体积渲染结论。

真实工作台每帧更新火焰历史的回放，小窗口 37.9 FPS、大窗口 44.9 FPS，渲染中位数 13.3/9.9ms。这两项是新增案例，没有旧版本同项对照，不给出火焰加速倍数。

1536 总览重绘到完整清晰帧约 464ms（小窗口）/868ms（大窗口）；包含现有 150ms 等待与分批补绘调度。完整图像耗时与预览 FPS 分开记录，没有降低原生分辨率或缩小预览来取得以上收益。

1536 总览三维测后工作集约 413MiB（小窗口）/330MiB（大窗口），全进程累计峰值约 832MiB。GC、并行任务和此前工作台火焰案例均计入；基线不含新增火焰案例，不能将两个进程峰值直接作为材质压缩收益。可以直接确认的是原始体素数组 252→31.5MiB，其他运行时占用并未等比例下降。短测试波动保留，不报告先前试跑的最好值。

## 剩余限制

仍是 CPU 射线渲染，世界本身是紧凑稠密数组与区块占据索引，未做 GPU Chunk 表面网格、贪婪合并、世界 LOD 或流式驻留。近景填满视口时射线更多命中细节，未必比缩小的全景快。分辨率越高，完整重绘成本仍会上升；静止缓存 FPS 不能代表动态场景容量。并行缓冲、任务与运行时 GC 的工作集有额外成本，8 倍体素压缩不等于进程内存减少 8 倍。

后续若需要大森林持续操作稳定 60FPS，重点评估 Chunk GPU 网格/远景 LOD 与静态森林、燃烧状态、火焰粒子的分离更新，不能只继续提高 CPU 预览分辨率。视觉仅检查资源和基础位置，整体效果由用户审查。
