# 大森林容量测试与 FPS 开关（v0.4.1）

P5 继续暂缓。Esc → 显示选项 → 右上角显示帧率，默认关闭，中英文均可用。开关保存在不上传的 settings.local.json，兼容旧的仅语言配置。显示最近至少 500ms 的实际帧间平均值，包含绘制、事件处理、等待与卡顿；刚启动显示 `--`，菜单打开时仍显示。它不是单次场景重绘耗时的倒数。

## 重现

正常工作台：`./run.ps1`。大森林独立入口：`./forest-stress.cmd`，或 `./forest-stress.ps1 -Example examples/large-forest.json`。Tab 切换三维/正上方纹理视图，C 高亮最大连通区域，Home 适配整个场景；三维支持右键旋转、中键平移和滚轮缩放，Esc 退出。

完整测量：`./forest-stress.ps1 -Benchmark`。关闭窗口可取消，CSV 保留完成的行；重新运行覆盖本轮 forest-benchmark.csv 和 forest-workbench.csv。这是独立加载/渲染测试。场地规划、保存格式、火势计算和搜索仍保持原有 24×20 合同，诊断 JSON 不能当作 .firebreak 打开。

启动器单独设置 `cjHeapSize=2GB`，退出后恢复环境，不改变普通启动器。首次原环境测试至 1024 成功、创建 1536 时出现 Out of memory，保留了 [默认堆 CSV](../artifacts/forest-default-heap.csv)。1536 的 Int64 体素数组独占 252MiB，尚未包含其他数组。仓颉文档说明默认堆通常为 256MB，见 [runtime 环境变量手册](https://docs.cangjie-lang.cn/docs/1.0.1/user_manual/source_zh_cn/Appendix/runtime_env.html)。扩大堆后已完成所有案例；内存分配问题和渲染性能需要分别判断。

## 生成与计数

默认 1536×1536、seed=42、占据参数 0.74。32 格尺度的双线性随机场调制逐格随机占据，形成疏密斑块；参数不等于精确覆盖率。沿用现有每四格放置、固定树干/树冠的模型，不增加树形算法。只在符合放置格且有燃料的根位置生成，树冠裁剪到燃料区域。

最大案例有 2,359,296 个地表格、1,747,032 个燃料格、109,253 个实际树模型；四邻接最大燃料连通区域 1,660,903 格。燃料格与树模型不能混称。连通示意图另用 512×512 两组占据参数，亮色为最大燃料区域；没有执行“放任燃烧/见火就扑”政策比较。空间相关生成不适用独立格点渗流的固定阈值。

## 实测

2026-11-02，仓颉 1.0.5、-O2；i7-13700H、20 逻辑核、15.64GiB RAM。系统报告 Iris Xe、RTX 4060 Laptop 及虚拟显示适配器；SDL driver=direct3d11、vsync=1，未确认实际 GPU。场景射线追踪仍在 CPU，Direct3D 用于纹理呈现。硬件摘要不含设备标识。

以下为首次扩大堆后的结果（CSV 保留最终源码复跑数据，数值会有正常波动），1280×860 窗口、三维画布 950×578。每循环预热 3 帧、采样 24 帧，每帧保留现有 12ms 等待。静止使用完整原生分辨率缓存；旋转每帧失效并触发最高 640px 宽预览。诊断 HUD 与实际工作台 UI 分开测量。

1536 在 2560×1380 窗口、2230×1098 三维画布下：完整 CPU 重绘 365.9ms、从失效到完整清晰帧约 1.28s、旋转预览 17.2 FPS。全屏旋转更快不代表像素越多越快：预览固定宽 640，纵横比改变预览高度、可见射线及森林覆盖面积，完整画布成本仍增加。

1536 正上方视图：小窗口完整画面 482×482，重绘 46.3ms，连续强制刷新 16.0 FPS；大窗口 1002×1002、199.9ms、10.3 FPS。二维强制刷新是同一投影反复失效，不是二维相机旋转。原实现预览固定宽 640，小地图预览可能比最终画面像素更多，本轮保留以测现状。

真实工作台原有小场景：1280×860 静止 64.5 FPS、旋转 22.6 FPS，渲染调用中位数 1.55/31.97ms；2560×1380 为 70.3/34.6 FPS。FPS 包含等待，渲染中位数不含显式 12ms 等待。短测试受系统负载、GC、呈现调度影响，保留 256 静止低值，没有反复选择最好成绩；未做长期稳定性或大型火势工作负载测试。

1536 三维测量后的工作集约 487MiB，完整进程累计工作集峰值约 747MiB。峰值包含先前案例和临时分配，不能归因于单张森林或视为显存；252MiB 原始体素也不等于进程全部内存。

## 判断和后续

十万级树模型可以生成和显示，静止缓存成本低；持续操作约 13–17 FPS，尚不适合作为最终大森林交互实现。应优先优化重绘路径。当前是稠密 Int64 体素、CPU DDA 和逐像素 Surface 写入，尚无 Chunk、两级 DDA、LOD 或 GPU 网格渲染。

下一步候选：减少射线临时数组及逐像素 FFI，批量写像素；增加区块占据索引/两级 DDA；远景汇总或 LOD、近景保留体素；需要连续大范围旋转时再评估 Chunk 网格 GPU 光栅化。这些是代码和测量支持的候选方向，尚无分项 A/B，不能宣称某一项已经被证明是唯一瓶颈。本轮不顺带重写渲染器。
