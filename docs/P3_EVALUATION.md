# P3：同情景方案比较

所有模型、后台任务、统计、界面和文件输出均由仓颉实现，继续使用 SDL3 显示原版纹理。网格仍为 24×20；本阶段没有扩大森林或引入 Chunk/LOD。

## 冻结输入与配对

评估开始时序列化完整场地和处理方案，记录 Workbench revision。原始场地忽略处理掩码；处理方案将处理格设为不可燃。两者不会修改正在编辑的文档，也不会修改对方的燃料或快照。

每个 Scenario 包含 id、起火格、seed、权重；规则版本为 1，风为 none。界面支持 4 / 16 / 32 组；内部上限 64。生成器优先保留已设置且可燃的起火点，再从原始林地按行优先索引的分位位置补足至多四个不同起火点，循环位置并递增 seed，等权。它是确定性试算集合，不是地域均匀抽样、独立真实观测或真实发生概率分布。

同组基线/方案使用完全相同的起火格、seed、传播概率和燃烧持续步数。随机键沿用 P2 的 `(seed, step, from, to)`；不同方案不移动共享随机流的位置。处理覆盖起火格时，方案初始燃烧为空，记录 `ignition_blocked=true`；该样本不会被跳过或换点。

序列化 Float64 使用 17 位有效数字，避免默认字符串精度导致快照/重新读取后模型参数改变。项目格式仍为 v2，兼容已有 v1/v2。

## 后台任务与失效

EvaluationJob 只在后台进行仓颉模型计算，不操作 SDL、纹理或窗口。进度和结果通过 Mutex 发布；每个仿真步和样本之间检查取消。只发布完整批次。除情景 1 保存完整回放外，其余情景只保留当前快照和最终指标，减少批量历史占用。

界面轮询结果，在主线程建立左右场景。编辑、撤销/重做、加载及参数变更引起 revision 变化，会取消旧任务、清除旧结果并关闭其图形资源；即使旧后台任务稍后结束，也不能覆盖当前结果。重新开始同样取消旧批次。取消不回滚已完成的场地编辑；取消中的部分结果不能导出。

## 指标

- 烧损：最终 age=-1 的原始林地格数。
- 清理：方案处理掩码非零格数，基线为 0；与烧损分开。
- 剩余：原始林地数减清理、减烧损；每个样本检查守恒。
- 目标接触：保护格自身或四邻域出现燃烧时累计该保护格。不是建筑烧毁或经济损失。
- 步数：该侧停止燃烧时的仿真步，不是现实秒数。

均值计算为 `sum(weight × value) / sum(weight)`。目标接触样本数是未加权次数，标明分母。无效、无收益或较差样本不会因表现不佳而删除。报告列出方案烧损或目标接触高于基线的样本数，不保证治理在本模型下总能改善全部指标。

## 显示和导出

左右共用相机、投影和回放步；先燃尽的一侧停在最终状态。回放仅展示情景 1，右栏统计包含完整批次。地图使用同一体素几何和 MC 纹理，不用色块替代真实场景。目标位置有青色标记，累计接触改为红色。

导出选择父目录，先在同一父目录写入临时目录，所有文件完成后使用不覆盖目标的 Windows 重命名发布独立目录。已有报告保留，失败时保留临时目录并显示位置。

| 文件 | 内容 |
|---|---|
| site.firebreak | 本次评估冻结的完整场地/方案及模型参数 |
| parameters.json | 规则、无风、revision、精确传播概率、燃烧步数及全部情景/权重 |
| metrics.csv | 每个情景、每一侧的全部整数指标、seed 和权重 |
| report.md | 加权汇总、目标接触次数、清理费用、采样方法与适用限制 |
| baseline.png / planned.png | 情景 1 最终状态的 384 像素宽纹理俯视；高度保持场地宽高比 |

导出 PNG 不叠加交互选区、UI 边框或动画，不是全样本风险热力图。图片输出在主线程同步执行；极端宽高比可能短暂等待。样本、报告不包含模型密钥或用户原始底图路径。

当前模型没有风、湿度、坡度传播、飞火、自动扑火、建筑燃烧或现实校准；样本比例不能解释为现实火灾概率。后续 P4 增加预算约束下的方案候选比较，P5 再接入已确认的电脑终端智能体。
